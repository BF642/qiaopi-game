# 2.1.0 南洋谋生：开发与验收说明

本文件说明当前实现的规则边界、复核方式和本轮验收记录。玩家可先读 [版本说明](../2.1.0版本说明.md)，贡献流程见 [CONTRIBUTING](../CONTRIBUTING.md)。

## 四项功能与实现位置

| 功能 | 主要文件 | 要保留的行为 |
|---|---|---|
| 实体欠薪事件 | `NanyangLife.cs`、`NanyangTasks.cs`、`WorldNanyang.cs` | 从第一份自由工作工资扣四份；选方案不结账；按步骤实际完成后才追回款项 |
| 三职业三级职责 | `NanyangLife.cs`、`LifeJourney.cs`、`NanyangTasks.cs` | 只按已完成同类自由工作的日志计算，最高三级；不可通过接单、放弃或重复读档刷经历 |
| 经历家书与妻子生活 | `ExperienceLetters.cs`、`PersonalLetters.cs`、`WorldPersonalLetters.cs` | 原文保留；回批使用已记录经历、心意与附银；首日延迟寄信优先；新章显式等待和收信 |
| 四区生活与记忆 | `NanyangPlaces.cs`、`WorldNanyangArt.cs`、`WorldNanyang.cs`、`WorldLivelihood.cs` | 实际站立点与道具位置分开；饭摊、床边、书桌可接近；熟人记忆随进度变化 |

以上运行文件均在 `Assets/Scripts/`。三个海外目的地继续共用主线与职业规则，场景表现有所区别，不应写成三套完全独立的长篇故事。

## 状态与结算边界

存档新增 `nanyangVersion` 和 `nanyang`。版本为零的旧档保持原有规则；只有符合接入条件的自由谋生起点才开始新版章节，不能以载入存档为由重置已经做过的轮次。首日仍使用独立的 `firstDayVersion` / `firstDay`，须先完成首日流程。

| 阶段 | 进入条件与下一步 | 必须可恢复的内容 |
|---|---|---|
| `free` | 安排工作、养身或访问四区；第一份实际自由工作结算后进入 `choice` | 所在生活区、工作进度、已吃饭轮次 |
| `choice` | 显示议定、实领、欠款，选定 `evidence`、`together` 或 `leave` | 欠款四份、原职业；选方案不会发钱 |
| `tasks` | 按保存的零起始步骤逐项办理；最后一步结算并进入 `letter` | 当前方案、步骤索引、追回额、生活日志 |
| `letter` | 桌前寄出 → `waiting`；留下草稿 → `complete` | 原稿、收件人、心意、附银、寄信次数和令牌 |
| `waiting` | 显式选择数周后的回音 → `reply` | 已寄原文、待收回批；此时信匣尚无新回信 |
| `reply` | 到批局领取一次 → `complete` | 待收内容、是否已经领取 |
| `complete` | 继续最多六轮生活，或满足三轮与无待办条件后继续主线 | 职业经历、换工补助是否用过、来往信件 |

`choice`、`tasks`、`waiting`、`reply` 中只能存稿，不能另寄一封绕过章节。`letter` 允许本次交寄；`free` 与 `complete` 按普通寄信规则处理。首日活动时仍先按首日规则判断，不得让新版家书提前触发或取代首日回批。

| 方案键 | 步数 | 最后一步追回 | 其他一次性结算 |
|---|---:|---:|---|
| `evidence` | 3 | 3 | 体力 −2、信用 +8，剩余欠款 1 |
| `together` | 2 | 4 | 体力 −4、信用 +5 |
| `leave` | 2 | 0 | 体力 +6、信用 +3；下一次完成不同于原欠薪职业的自由工作，补助 2，仅一次 |

欠薪只减少当次实领工资。不要把追回款当作另一轮劳动、再次扣健康或多写一条工作经历。`CompleteStep` 必须拒绝过期步骤；读取界面、保存、恢复或再次点击均不能重复结算。

三级职责由同类已完成自由工作的次数 0 / 1 / 2 对应可接级别 1 / 2 / 3。完成首日、休息、寄家用以及欠薪应对都不增加职业次数。六轮是生活安排上限，满三轮只是继续主线的最低条件，还须处理欠薪、寄出并收妥本次回批或选择留稿，且不能有尚未结账的工作。

## 家书与兼容性

- 回批只读取保存的游戏事实。没有欠薪记录不能写欠薪；低体力不能当成受伤；旧版槟榔屿或仰光的其他受挫事件不能被当作新加坡欠薪。
- 母亲、妻子、妹妹保留不同称呼与关注点。妻子针线订单、材料账、识字和合接订单的计划按本程此前已寄信总数推进，不另存或伪造玩家婚姻经历。
- 不解释玩家自由输入的全文。原文原样保存，收件人、心意、附银和经历才决定回批段落。已经保存的旧信不重新生成。
- 一程自写批上限三封，原文上限 1200 字符，附银为 0 / 2 / 5 / 8。额度用尽仍允许在章节留稿跳过，不能卡在写批阶段。
- 待收回批占用信匣预留容量。40 封总容量下，寄出后的 39 封加一封待收必须可领取；不得利用首日与新章各自的预留逻辑超出总量。
- 交寄失败必须完整恢复钱款、属性、旗标、计数、令牌、草稿及信件列表。过期或重复令牌不扣款、不清稿、不新增来回信。
- 新章寄出后，先保存待收回批；数周转场不再扣款，领取只添加一次。章节外普通交寄保留原有叙事时间跳转行为。

## 当前检查入口

Mac 与 iOS 构建脚本已接入 `FirstDayChecks.Run()`、`NanyangChecks.Run()` 和 `ExperienceLetterChecks.Run()`。后两者没有单独 Unity 菜单项，不应在贡献指南中虚构菜单。

| 检查 | 文件与重点 |
|---|---|
| 首日回归 | `Assets/Editor/FirstDayChecks.cs`：九种首日选择、阶段恢复、结算与奖励一次性、延迟回批、旧版本兼容 |
| 南洋规则 | `Assets/Editor/NanyangChecks.cs`：目的地 × 职业 × 三应对 × 寄出或留稿、存档往返、三职业三级、六轮上限、饭摊与养身、换工补助 |
| 经历回批 | `Assets/Editor/ExperienceLetterChecks.cs`：不捏造经历、收件人和心意、附银、妻子连续生活、交易回滚、容量与重复寄收 |
| 第一人称运行 | `Assets/Scripts/WorldNanyangQA.cs`：物理交互、分支步骤、桌前写批、数周转场、收信、阶段保存恢复及画面 |

从构建后的应用启动时，`-qiaopi-nanyang-test` 进入隔离的完整运行检查。追加 `-qiaopi-nanyang-review` 仅做短程画面与四区交互检查，不能当作完整游玩验证；追加 `-qiaopi-touch-preview` 查看触屏布局，不能当作 iPhone 实机验证。截图目录由日志 `NANYANG_QA_OUTPUT` 给出；完整通过标记为 `NANYANG_RUNTIME_ALL_PASSED`，短程标记为 `NANYANG_REVIEW_ALL_PASSED`。

职业专项入口为 `-qiaopi-nanyang-test -qiaopi-nanyang-career-review`，从合法的二级起点逐一完成三个职业的二、三级任务。每次核验必须在正常到达后的第一次互动打开，不能靠反复绕行掩盖熟人聊天抢占互动。信用在交工时按当级待遇统一发放；核对一张后放弃、重接不会留下信用奖励。通过标记为 `NANYANG_CAREER_REVIEW_PASSED`，不代表完整欠薪与寄信流程。

隔离入口使用合成状态与临时存档，保持静音，并核对真实存档和音量偏好未改动。它会读取原文件作前后比对，不用玩家原档跑测试；测试报告、截图和日志也不应包含玩家的私人信件。

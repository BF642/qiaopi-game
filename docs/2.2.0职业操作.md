# 2.2.0 职业操作：开发状态与验收入口

2026-10-08。已完成本地 2.2.0 构建、三职业九等级组合的实际运行检查和桌面触屏短程预览；随后修正门边回执的摆放，最终构建的定向复查记录见下。公开下载不会随本机自动更新，本轮没有发布 GitHub Release 或安装 iPhone 版本。

## 本轮实现

南洋首日与正在进行的旧任务沿用原流程。进入自主谋生后，新接的码头、杂货铺、批局工作改用现场操作；原有三至六轮生活安排、三种欠薪应对、家书与八类结局继续衔接。

| 职业 | 一级 | 二级 | 三级 |
|---|---|---|---|
| 码头 | 两件米粮／布匹按货签分区入栈 | 三件货，先将怕潮纸货送入棚 | 三件货的排列改变，仍须先送纸货，不能死记顺序 |
| 杂货铺 | 称一斤米，货钱四份、收十份、找六份 | 称一斤半米，货钱六份、收十份、找四份 | 称两斤半米，货钱九份、收六份、不找零，将三份记入赊欠 |
| 批局 | 看批封、问路、核南街三号本人、交批取回执 | 同名收件人改到北巷七号，需按批封核门牌 | 回到南街三号，再完成本人核收与回执留底 |

三种工作按操作方式区分；批局各等级沿用同一交批流程，三级没有额外新谜题。称量以半斤为一个操作单位；柜台的“份”是游戏简化计数，不表示历史币制或兑换关系。

码头通过 E 取放，拿错顺序或放错货栈会说明原因并保留货物。杂货铺可以添米、取米，将一／二／五份钱放入或取回找零盘；秤梁、米量、钱盘随操作变化。批局两位同名角色各有固定门牌，必须本人核认，交批后另取回执。纸面界面放在右侧；镜头按称量、钱盘或账簿切换，保留左侧实物视野。已查看桌面与横屏触屏预览截图；尚未做 iPhone 真机验证。

## 状态与兼容

- `GameState.tradeShift` 保存当前新工作阶段，旧存档字段为空或版本零均为未启用；只在下一次接活时初始化。
- 现场操作不更改盘缠、身体、信任、生活轮次与主线决定数。完成后到雇主身边，统一通过原 `LifeJourney.CommitAction` 结算。
- 一级自由工作仍衔接欠下四份工钱的事件；后续等级沿用原工资与疲劳规则。
- 放弃换工清空本次操作，不付工资、不增加轮次。完成状态读档后仍须到雇主处结账；已结账不可重复领取。
- 新工作用独立阶段记录，旧 `progress/carrying/inspected` 不得混填；保存校验拒绝互相矛盾的数据。
- 抱着新货包或侨批时不能落座写信。空手时仍可去写批处；返回工作要重新接近操作点。
- 新固定人物与操作站位加入日常行人的避让区域，避免背景人物重叠；未更改已有角色资产。
- 保持原静音偏好。新操作面板本轮没有新增句子配音。

## 可重复验收

1. 在允许 Unity 正常运行的环境，打开 Unity 6000.6.0f1 工程。执行 **侨批 → 导出 Mac 游戏**，先运行已接入的剧情、保存、首日、南洋、家书和职业规则检查。
2. 对新构建运行完整职业验收：

```sh
"Builds/侨批·纸短情长.app/Contents/MacOS/侨批 · 纸短情长" \
  -qiaopi-trade-test \
  -qiaopi-trade-output "$PWD/TradeQA" \
  -screen-fullscreen 0 -screen-width 1440 -screen-height 900 \
  -logFile "$PWD/TradeQA-full.log"
```

可执行文件名以构建产物 `Contents/Info.plist` 的 `CFBundleExecutable` 为准。`-qiaopi-trade-output` 应指向可写目录；不传时桌面使用系统临时目录。测试状态从合成的各级职业起点创建，通过真实第一人称行走与正式交互函数执行；不能称作从泉州开场一路玩到结局。

追加 `-qiaopi-trade-route courier` 可只检查送批职业，仍覆盖三个等级和弃工；也支持 `dock`、`shop`。最终日志按实际完成组合数报告，错误参数会直接报错。

追加 `-qiaopi-trade-review` 只验证一级短程流程；默认三职业，搭配职业筛选则只检查选中职业。再追加 `-qiaopi-touch-preview`、使用宽 1600 高 737，可检查桌面触屏布局；这仍不是 iPhone 真机测试。

完整检查覆盖误操作拒绝、货签与怕潮优先、称量／找零／赊账、同名者核对、回执、雇主单次结算、弃工重接、临时磁盘保存恢复及原存档与静音偏好不变。保存测试按阶段重建场景，不仅检查一口气完成。错误路径与正常路径必须全部通过，并人工查看截图。

旧进行中任务另用既有 `-qiaopi-nanyang-test -qiaopi-nanyang-career-review` 验收。该旧入口刻意不启用新职业状态，以覆盖原任务兼容。不要用真实玩家存档做测试夹具。

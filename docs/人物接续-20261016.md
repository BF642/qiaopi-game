## 跨电脑加载修复

Unity 在 Windows 上重导入资源后，依赖哈希可能不同于 Mac。此前 NativeMotionSet 的旧验收记录会让已接入的模型被编辑器拒绝，回退至旧角色。现在 directImport 明确跳过这项美术验收哈希门槛，仍要求有效版本、模型和必要动作引用。妻子和帮工也启用 directImport，其既有原始资源和适配不变；未启用直接导入的旧验收路径仍保留。

已验证三位新角色的工厂加载、八位已有角色继续选用原动作模型，以及直接导入允许平台哈希变化、缺少必要动作仍拒绝加载。Unity 编译通过，Windows 构建输出 DESKTOP_HANDOFF_BUILD_SUCCESS，独立成品启动输出 QIAOPI_LOGIN_READY。未执行逐资产美术、动作或网格验收，也未进行整条剧情通关测试；未进入玩家旅程或读写存档。

## 必要的重新导入方式

1. 使用 Blender 后台执行 `tools/import_existing_cast.py`，在 `--` 后依次传入工程目录、角色名和现有 GLB 路径。这只做保留几何的格式与绑定转换。
2. 用 Python/Pillow 执行 `tools/pack_native_metallic.py`，参数为该角色的 MeshyMotion 资源目录。
3. 在 Unity 中调用 `Qiaopi.Editor.ExistingCastImport.Install("角色名")` 连接原生贴图、材料与现成动作。通常正常克隆后不需要重跑导入工具。

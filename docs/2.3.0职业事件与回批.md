# 2.3.0 职业事件与回批：开发状态与验收入口

2026-10-08。新增六个职业事件、十二种选择，以及依据已结算工作生成的熟人记忆和家书回应。两套 Mac 工程已通过 Unity 构建与项目规则检查；十二选择分支实际运行和二级六分支桌面触屏预览已通过。本轮未发布 GitHub Release，未作 iPhone 真机验证。

## 进入方式

完成南洋首日，在自主谋生阶段继续接工作。同一职业二级、三级的新工作各触发一个事件；第一轮仍保留职业入门和原有欠薪流程。码头、铺里的商量发生在工作站位，送批先读批封，再到街坊处了解情况。

选择不等于完成：选好后仍要走动搬货、称量记账或核人交批；最后回雇主身边交工才结算。已有进行中的 2.2.0 工作不追加事件，下次符合等级的新工作才启用。每程仍安排三至六轮生活，每种工作最多三轮；不保证一局看到全部事件。

## 六个事件与十二种选择

下表工钱变化相对该职业、该级别原工资，全部在交工时生效。身体与信用的附加变化会在现场选项中说明；柜台的“份”为游戏简化计数，不代表历史币制。关系变化用共同经历表达，不要求玩家刷满一条好感数值。

| 事件 | 选择 | 实际操作与代价 |
|---|---|---|
| 码头二级：雨前护纸 | 自己先把纸货抢入棚 | 自己搬纸货、米粮、布匹三件；工钱不加减，比原工作更费体力。 |
| 同上 | 与工友分工 | 工友接走布匹，自己搬纸货和米粮；工钱少两份，少耗一些体力，留下共同分担的经历。 |
| 码头三级：新来的同工 | 教他认货签 | 同工照货签接走布匹，自己搬另外两件；工钱少一份，留下教人分货的经历。 |
| 同上 | 自己接完三件 | 三件货都由自己搬；工钱多两份，也更费体力。 |
| 铺里二级：熟客的钱不够 | 照原量称货，记赊欠 | 一斤半，价六份、实收四份，另记欠二份；欠款不能当作现钱。 |
| 同上 | 商量改称一斤 | 一斤，价四份、实收四份；少卖半斤，不增加赊账。 |
| 铺里三级：独立管账 | 现钱与赊欠分开记 | 两斤半，价九份、实收六份，另记欠三份；交清账后工钱多一份。 |
| 同上 | 改称一斤半 | 一斤半，价六份、实收六份；少卖一斤，不增加赊账。 |
| 批局二级：收件人搬家 | 问清新住处，再核本人 | 批封旧址是北巷七号，线索指向南街三号。到新址核本人、交批、取回执，多跑一程。 |
| 同上 | 原封退局 | 回批局柜台登记未交付；相对正常送达少领六份工钱，没有收件人回执。 |
| 批局三级：邻人愿意代收 | 坚持本人核收 | 仍去南街三号核清本人后交批，收回本人回执；不让邻人代签。 |
| 同上 | 原封退局 | 回批局登记尚未亲交；相对正常送达少领七份工钱，没有收件人回执。 |

搬家事件中的收件人身份不随选择或读档交换。批封保留旧址，街坊线索和新住处分别表达迁居情况；不是把两名同名角色当成同一个人。退批有独立的“回局登记”步骤，登记后还须交工结账，不能将退回写成成功送达。

## 关系与家书的边界

- `GameState.workMemory` 保存已结算事件，记录职业、等级、选择、生活轮次和是否退批。选择之后、操作未完、做完尚未结账、弃工时，都不写入已完成记忆。
- `WorkRelationshipText.Greeting` 按该职业最近一次真实记录给出短问候；生活簿最多列三行不同职业的共同经历。原有许生近况也可引用这些记录。
- 家书优先回应最近一次已结算事件。母亲关心吃住与分寸，阿满侧重认字和账目，妻子结合自己的针线订单、材料开支与收付安排作答，三人的语气和关注点不同。
- 自由正文仅保存在本机。回批选择器不解析、上传或改写正文，不把玩家写下的未经游戏记录的经历当作事实。
- `ExperienceLetters.Reply` 仍由寄信流程在交寄时生成；已有信件与等待中的回批保持原文。新工作只影响以后寄出的回批，不反向修改旧信，也不会自动替玩家寄出新信。
- 回批里的“自写侨批附银已收”指玩家寄给家里的那封信；职业里原封退回的另一封批仍明确未送达，两笔银信不可混为一谈。

## 状态与源码位置

| 文件 | 责任 |
|---|---|
| `Assets/Scripts/WorkEvents.cs` | 事件、选项、已完成记录、关系规则与版本校验 |
| `Assets/Scripts/TradeWork.cs` | 按事件选择改变搬运、称货、记账、核收和退批登记 |
| `Assets/Scripts/LifeJourney.cs` | 统一结账，应用事件额外变化并写入一次完成记录 |
| `Assets/Scripts/WorldWorkEvents.cs` | 现场商量、熟人问候、生活簿关系摘要及搬家交互 |
| `Assets/Scripts/WorkRelationshipText.cs` | 依据真实记录选择人物声音和家书段落 |
| `Assets/Scripts/ExperienceLetters.cs` | 将该段落接入原回批，继续保持寄出时定稿 |
| `Assets/Editor/WorkEventChecks.cs` | 十二种选择、三目的地、结账与兼容的纯规则检查 |
| `Assets/Editor/WorkRelationshipChecks.cs` | 三位家人声音、未完成经历排除及旧回信不变检查 |
| `Assets/Scripts/WorldWorkEventQA.cs` | 合成职业起点后的第一人称实际操作与隔离存读检查 |

新事件采用可选版本字段。`tradeShift.incident` 为空或零版本的旧任务继续原操作，`workMemory` 为空或零版本且无记录时表示尚未启用记忆。放弃工作只清除本次工作阶段；不会扣回已结算工钱，也不会抹掉过去的熟人记忆。加载时拒绝未结账却出现完成记录、记录轮次与行旅日志不符、退批状态互相矛盾等数据。

## 可重复验收

在 Unity 6000.6.0f1 中运行 `WorkEventChecks.Run()`、`WorkRelationshipChecks.Run()`，并保留原有 `TradeWorkChecks`、`ExperienceLetterChecks`、南洋与首日检查。修改事件后至少覆盖选择前后、操作完成但未结账、结账后重复点击、弃工重接及各阶段读档。不要把旧任务自动升级为新事件。

正式构建后的独立运行入口：

```sh
"Builds/侨批·纸短情长.app/Contents/MacOS/侨批 · 纸短情长" \
  -qiaopi-work-event-test \
  -qiaopi-work-event-output "$PWD/WorkEventQA" \
  -screen-fullscreen 0 -screen-width 1440 -screen-height 900 \
  -logFile "$PWD/WorkEventQA.log"
```

可执行文件名以 `Contents/Info.plist` 的 `CFBundleExecutable` 为准。输出目录必须可写。入口使用合成的各职业等级起点，再走正式第一人称移动、现场选择、工作操作和雇主结账；不是从泉州开场通关十二遍。

追加 `-qiaopi-work-event-route dock`、`shop` 或 `courier` 可只查一个职业。追加 `-qiaopi-work-event-review` 只跑第二级的两种选择与弃工，不能写成二、三级全部通过。追加 `-qiaopi-touch-preview` 仅表示桌面触屏布局预览，建议使用 1600 × 737 窗口；不能替代 iPhone 真机测试。

检查使用临时存档并核对真实存档和静音偏好未变。不要把玩家真实信件当夹具；需要同时查看截图中的门牌、人物、选项完整性和回信文字。普通 2.2.0 职业兼容另用 `-qiaopi-trade-test` 检查。

# 2.4.0 人物与工作动作：实现范围与验收入口

2026-10-08。本轮实现第一人称职业动作、工友的实际布匹搬运，以及现场人物和对话肖像的转头、点头与工作姿态。**协作工程与本机配音工程的最终 Mac 构建成功，七个桌面场景的完整操作检查通过；后续视觉与时序修正后，三个代表性场景的实际运行和基础画面接触复核通过。** 本机最终构建的横屏触屏预览也通过三个代表性场景。各项范围和仍待补充的记录见下文。

## 从哪里体验

完成南洋首日，在自主谋生阶段接码头、杂货铺或批局的工作。第一人称工作动作接在现有职业操作上，不增加新的劳动轮次。同一职业二级、三级的新工作继续使用 2.3.0 的职业事件；选择“与工友分工”或“教他认货签”后，可以看见阿顺搬走自己的布匹。

动作持续约一至一点五秒；演出时暂时收起工作面板并挡住重复互动。称米、找零、记账的下一步仍需玩家操作，结束后恢复对应面板。桌面按 Esc，或桌面、触屏点击“收起动作”，可以立即结束当前展示。声音沿用玩家已有设置，不因增加动作重新开启。

## 三种职业的现场表现

| 工作 | 可见动作 | 与规则的关系 |
|---|---|---|
| 搬货 | 取货时视线与双手下探，再托起货物；放货时向前送出。米袋、布匹、纸货各有持物形状。 | 仍须看货签、按顺序把货送到正确货栈。动作不另给工资或信用。 |
| 称米 | 木勺、勺中米和倒入秤盘的米粒；取回多称的米时空勺伸出、带米收回；秤梁和悬盘一起变化。 | 数量仍由玩家添减；不正确的称量不能确认，也不会播放成功确认动作。 |
| 找零与记账 | 数钱、放入或取回钱盘中的零钱、核清货钱；左手托起近景账本，右掌握笔，笔尖在纸面记账；客人作出回应。 | 按这笔实际找零显示钱币；不需找零时不凭空变出零钱。赊欠不算实收现钱。 |
| 送批 | 收好批包、交到已经核认的人手中；收件人持纸签认时玩家放低双手等待，然后接回一张薄纸回执。 | 核人、交批、回执仍是不同步骤。玩家不替收件人签字，也不会把交出去的整捆银信当作回执再拿回来。 |
| 原封退批 | 把未能亲交的银信送回柜台。 | 必须回批局登记未送达；退批没有收件人的收讫回执。 |

这些是职业操作内的现场演出。既有首日、主线、附银、延迟回批和结局规则继续沿用，不能把本次增加的动作算作新增剧情路线。

勺碗按实际米盘的画面位置伸出，秤盘变化时工具目标随之变化；勺柄保持在掌心，勺碗转到手的上方以减少衣袖遮挡。记账改为把本子拿到手边，避免把整双前臂向远处柜台平移；手持账本出现时隐藏柜台上的对应本，取消或结束后恢复。

第一人称双手已恢复完整五指的真实网格，衣袖连续延伸到画面下沿。Blender 源文件是 [`美术源文件/第一人称双手-2.4.0.blend`](../美术源文件/第一人称双手-2.4.0.blend)，游戏资产是 `Assets/Resources/Models/FirstPersonHands.fbx`。最终协作构建导入 3 个网格、17,908 个顶点，尺寸约 0.840 × 0.696 × 0.906 米；构建检查要求该资产实际存在且含有效几何，不能静默用简易手形替代。此处是手部资产恢复，不是新增人物脸型或完整角色模型。

## 工友搬的是一件真实场景物件

二级分工时，阿顺先回应，再去布托拿货。三级教同工时增加认货签的指点，随后拿起同一件布包。工友沿可行走路线移动、避让玩家和其他人，把布包放到布车上后停留。他有抬起、抱货、行走和放下姿态；货物跟随双臂，不用瞬间隐藏一个道具再在远处凭空生成一件来代替搬运。

这段配合只负责表现自己分到的工作。玩家仍按当前选择搬两件，交工时按原规则结账；工友走到一半或重复看演出不会增减钱、关系、旅程轮次或玩家的交货记录。

为了让旧存档可恢复，展示不写入新的持久化动画进度。已经开始抱货或交过一件的工作，重载后把工友和布包恢复在完成分工的位置；刚作出选择、玩家尚未开始搬货的存档，可以从起点重演这段配合。重演不会重复计算任务或工资。

## 人物姿态与外观边界

`CharacterPerformance` 在现有模型上控制双臂、上身和头部。现场交谈会逐渐转向说话的人，对话肖像用短促点头回应句子；工友有抱货与指点姿态，柜台客人会回应，收件人会递接并签认。

本轮不替换脸型、衣着或人物模型，没有口型同步、逐指抓握、手指逆向运动学或完整动作捕捉。第一人称手部动作与场景人物姿态分别控制；镜头中的手和工具必须经过实际截图检查，代码中的“动作开始”并不代表视觉效果已经合格。

最终代表性截图已确认米勺和砝码不再被衣袖完全挡住，近景账本的笔尖接触纸面；收件人双臂抬起，持纸签认后交回单张薄纸，等待阶段玩家双手不遮住收件人。当前手势仍偏直，掌中零钱较小、辨识度弱；这些属于后续自然度与清晰度改进，不宣称已经达到逐指握持或精细表演效果。

运行时扩展的上身关节使用各实例自己的网格，保留源模型资产。姿态检查覆盖中性外观、反复恢复、下肢位置、肖像副本和源网格不被修改，避免加动作后把脸或衣服拉坏。

## 提交、取消、读档与面板

1. 正式职业规则先核对站位、工作阶段、物件和数目；通过后同步记下操作并保存，再播放短动作。动画不负责发放奖励。
2. 动作忙时，重复互动、改另一件物品或选择不能再次改变状态。工作面板收起，手与道具保持可见。
3. 自然完成后，未结束的商店工作恢复当前正确步骤。称量仍看秤、交钱仍看钱盘；完成动作后才转向下一工作点。
4. 取消、切后台或重建场景时清理临时工具、姿态和遮挡。已经提交的操作保留，不能通过取消恢复一份货物再重复交付。取消后可以正常继续工作。
5. 工作完成后仍须回雇主处交工，才按原职业与事件选择结算工钱、身体、信用和共同经历。中途放弃仍不领工钱或写入完成记忆。

临时的笔、纸、当前动作种类和播放进度不进存档。旧版本工作状态继续读入；纯展示不会改写玩家已经寄出的家书，也不会解析自由正文。

## 体验时长怎么衡量

优先打磨的一段是“泉州家庭日常 → 离乡 → 海外第一份工作 → 首封亲手写的侨批 → 收到回音”。目标约 **20～30 分钟**，目前为设计估计，尚待真人完整试玩计时。该段收到首次回批即可形成一次完整的情感体验，不要求玩家先额外做完三轮自由谋生。

后续自主工作和人生结局是继续游玩的内容。不能用合成职业存档的验收耗时、自动行走时间或后续职业轮次，替代从泉州开场的真人游玩时长。

## 重复验收入口

正式 Unity 构建包含 `CharacterPerformanceChecks.Run()`，保留原有职业、事件、关系回批、存档与剧情检查。人物检查使用生产模型并验证姿态前后的实际几何；不只检验“有一个动画计时器”。

构建后的独立游戏运行入口：

```sh
"Builds/侨批·纸短情长.app/Contents/MacOS/侨批 · 纸短情长" \
  -qiaopi-performance-test \
  -qiaopi-performance-output "$PWD/PerformanceQA" \
  -screen-fullscreen 0 -screen-width 1440 -screen-height 900 \
  -logFile "$PWD/PerformanceQA.log"
```

可执行文件名以应用内 `Contents/Info.plist` 的 `CFBundleExecutable` 为准，输出目录必须可写。只运行一个游戏进程；检查期间不要把游戏切到后台，否则会触发正式的动作取消行为。

默认从合成的职业等级起点验证七个代表性场景：码头二级分工、三级教同工；铺里二级赊账、三级记账；批局二级追查新址、二级原封退局、三级亲交本人。随后使用正式第一人称移动、现场操作和雇主结账，不是从泉州通关七次，也不是 2.3.0 全部十二选择的重复验收。

- `-qiaopi-performance-route dock`、`shop` 或 `courier`：只查一个职业。
- `-qiaopi-performance-review`：只跑二级的分工、赊账、追查新址三个场景；可以与职业筛选组合。
- `-qiaopi-touch-preview`：使用桌面触屏布局，建议窗口 1600 × 737；不代表 iPhone 真机通过。

完整通过标记是 `PERFORMANCE_RUNTIME_ALL_PASSED`，短程标记是 `PERFORMANCE_REVIEW_ALL_PASSED`；日志记录实际场景数、动作数、临时存读数和断言数。截图输出位置由 `PERFORMANCE_QA_OUTPUT` 给出。

新验收检查动作过程中的实际手部和工具变化、重复按键不改变状态、取回多称的米不向秤里倒米、回执不会同时出现在两个人手里、工友确实走路搬货，以及动画中临时读档和取消后没有延迟奖励。测试使用临时存档，核对真实存档与声音偏好未变；不得把玩家真实信件复制成测试材料。

旧 `-qiaopi-trade-test` 和 `-qiaopi-work-event-test` 入口继续验证业务流程，跳过第一人称短动作以保留原步骤检查。它们通过不能代替新的动作验收。最后仍需人工查看截图中手、工具、秤盘、笔纸、货物落点和人物比例，确认没有穿模、悬空或界面遮挡。

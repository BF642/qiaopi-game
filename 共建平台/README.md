# 侨批图集 · 一纸共藏

这里存放共建图集的索引、图片与维护者审核工具。游戏收集与泉州侨批有关的家书、回批、批封、汇票、信局器物、老照片和文字材料。

**当前随游戏提供的配置没有在线收件地址或在线审核索引。游戏可以保存草稿、生成本机投稿包；它不会自动把材料发给任何人。** 内置图片均是标明「示意样张 · 非史料」的演示内容。

## 玩家：从材料到收入图集

打开游戏顶部「图集」→「准备投稿」。四步表单会自动在本机保存草稿。

1. **选材料**：放入并勾选 1–8 张 PNG / JPG / WebP 图片，每张不超过 8 MB。拍清正文与批封，不确定的年代可留空；请先处理不愿公开的个人资料。口述、文字材料可整理成图片随包提交。
2. **写题名**：填写 2–40 字题名、选择类别；年代、地点和往返路线选填。
3. **说明与授权**：说明材料是什么、谁寄给谁、与泉州的联系（至少 8 字）；填写持有人、原始出处、授权人或允许公开的依据，以及公开署名。确认自己有权公开这些材料。
4. **检查成包**：确认后点「生成投稿包 · 尚未递交」。这一步生成文件，**不等于上传成功或维护者收件**。
5. **手动递交**：到「我的投稿」找到完整投稿包，通过与维护者约定的方式交给对方。没有约定的收件渠道时，请先向游戏维护者索取渠道；游戏不会编造或代发收件地址。
6. **记录与审核**：实际交出后，可点「我已交给维护者」，登记递交给谁、通过什么方式或投稿链接。此记录是玩家自行登记，不是维护者收件确认。维护者审核并发布索引后，游戏才可显示收入或退回。

本地可以同时准备多份材料，生成包不会锁住下一份草稿。退回记录保留审核意见；「按意见修改草稿」会复制字段与图片引用，重新确认授权后生成新编号，原记录仍保留。

### 电脑与 iPhone 如何放入、取出文件

- **macOS**：在游戏点「打开投稿文件夹」。默认位置为 `~/Library/Application Support/studio.quanzhou.qiaopi/gallery/投稿/`。
- **iPhone**：在照片 App 点分享 → 存储到「文件」→ 我的 iPhone → **侨批·纸短情长** → `gallery` → `投稿`。回游戏点「重新扫描」，再勾选图片。HEIC 需先导出为 JPG。游戏的「查看文件 App 存放步骤」可随时查看这一路径。
- **投稿包**：在 `gallery/submissions/<投稿编号>/`，包含 `entry.json`、`投稿说明.txt`、图片与图片 SHA-256 校验值。必须递交整个文件夹。
- **iPhone 取出**：在文件 App 长按投稿包文件夹 → 压缩，再通过约定的渠道分享。游戏中的「查看投稿包位置」显示具体路径。

### 状态是什么意思

| 游戏显示 | 实际含义 |
| --- | --- |
| 草稿 | 表单和所选图片引用保存在本机，尚未成包 |
| 已打包 · 未递交 | 完整文件已生成，尚无递交记录 |
| 已记递交 · 待审 | 玩家自行记录已交出；游戏未确认对方收件 |
| 已收入图集 | 正式图集索引中出现相同投稿编号与提供者编号 |
| 退回修改 | 维护者为这份投稿发布了退回意见 |
| 旧记录 · 待核对 | 旧版曾把本地生成包直接写为 pending，没有递交凭据；请核对真实递交情况 |

旧版文件和历史不会被删除。旧 `pending` 不再被自动称为「已经递交」，也不会阻止准备新材料。

## 维护者：先接收，再审核

开发者需要先确定真实、可使用的收件渠道，并告知玩家。在未配置渠道前，游戏只提供整理与导出功能。本目录是可部署的静态仓库模板，本身不是已上线的平台。

审核时核对原图可读性、材料与泉州侨批的关联、来源与授权、署名和必要的隐私处理。新包附带授权确认标记；旧包缺少该字段时，应另行核实授权。审核工具还会核对图片文件清单与 SHA-256，避免收件不完整或内容被改动。

```bash
python3 tools/review_submission.py --list
python3 tools/review_submission.py <投稿包目录>
python3 tools/review_submission.py <投稿包目录> --reject "图片模糊，请补充清楚的照片"
python3 tools/review_submission.py --check
python3 tools/review_submission.py --rebuild
```

通过操作会保存图片并以**投稿编号**写入图集条目；退回会写入带 `submissionId` 的审核意见，不应把同一提供者的所有投稿一起退回。新游戏按投稿编号和提供者编号匹配结果，旧版单份 pending 记录仍可读取旧格式的审核意见。

本机审核完成还不等于已发布。维护者需要把更新后的索引和图片发布到配置的共建仓库，或者随下一次游戏更新分发。玩家有可用的索引地址时点「刷新审核结果」；没有时应直接向维护者索取结果。

## 接通真正的在线地址

在游戏存档目录放置 `gallery-config.json`（与 `qiaopi-world-v1.json` 同级），或在 `Assets/Resources/Gallery/index.json` 中设置字段。下面只展示字段结构，**占位地址不能用于收件**：

```json
{
  "indexUrl": "https://raw.githubusercontent.com/<维护者账号>/<已发布仓库>/main/gallery/index.json",
  "repo": "https://github.com/<维护者账号>/<已发布仓库>"
}
```

- `indexUrl`：正式审核索引地址。打开图集或手动刷新后读取，成功后缓存，离线显示缓存与内置内容。
- `repo`：真实 GitHub 仓库，需允许用户创建 issue，并部署 `.github/ISSUE_TEMPLATE/投稿.yml`。配置后出现「打开收件网页」，玩家仍需在网页手动附上完整投稿包并提交；打开网页本身不会上传文件或改变游戏状态。
- 两项留空时，游戏明确显示尚未接通在线收件/审核。不要用无效地址制造已经上线的假象。

游戏中的递交按钮只保存玩家输入的收件说明，不会替用户发送消息、创建 issue 或上传材料。

## 索引与旧记录兼容

```json
{
  "version": 1,
  "updated": "2026-09-27",
  "indexUrl": "",
  "repo": "",
  "contributors": ["QZ-1A2B3C4D"],
  "notes": [
    {"contributorId": "QZ-1A2B3C4D", "submissionId": "GJ-20260927-101010", "status": "rejected", "note": "请补充清楚的照片", "date": "2026-09-27"}
  ],
  "entries": []
}
```

条目延续原 `id`、`contributorId`、`title`、`category`、`description`、`source`、`image` 等字段。`sample` 非空时是示意样张标记，正式历史材料不应冒用样张，也不能把绘制的图片当作历史档案。

本机 `gallery-state.json` 新增独立 `draft`，投稿记录增加 `rightsConfirmed`、`handedOverAt` 与 `deliveryReference`。新增状态 `packaged` 和 `handed_over`；旧状态和文件保持可读。
